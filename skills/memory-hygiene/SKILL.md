# Memory Hygiene

When deciding what belongs in durable memory:

- Retain durable preferences, decisions, relationships between project concepts, and reusable facts.
- Do not retain passwords, API keys, session cookies, one-time codes, private keys, recovery codes or raw OAuth data.
- Minimize highly sensitive personal data unless the user clearly wants durable retention.
- Mark temporal facts with dates/context and supersede stale state rather than silently duplicating it.
- Keep project/profile memories separated when cross-contamination would be harmful.
